For centuries, the box window has been a defining feature of Vienna’s cityscape. It can be found throughout Europe, particularly in 19th-century buildings. Research into and further development of the box window are essential to sustainable con-struction in a regional context.
To rationalize the management of existing building stock, it is useful to determine the total number of these building components. For sustainable devel-opment, their quantity must be assessed to estab-lish the extent to which further development of box windows could reduce CO₂ emissions and save energy and materials.
This thesis develops a methodology for calculating the number of box windows in urban areas. The findings are intended to serve as an example and to be transferable to other building elements of structural or historical significance.
An object-detection model was trained using Ul-tralytics YOLO to identify individual window in-stances. In addition to distinguishing between box windows and non-box windows, the model pro-vides a broad classification of the window types commonly found in Vienna. This is intended to support further applications of computer vision in historic preservation and historical building re-search.
For model training, a collection of more than 1,000 facade images was assembled and annotated us-ing Label Studio. The classification system com-prises five box-window classes and five classes for other window types. The model achieves an mAP50 of 0.79 and an mAP50-95 of 0.69. For the three most important box-window classes (Galgenkastenfenster, Altwiener Kastenfenster, and Wiener Kastenfenster), mAP50-95 scores range from 0.74 to 0.83.
For the calculations, the trained model was ap-plied to publicly accessible Google Street View im-agery. This imagery is generally available and can be accessed through programmable interfaces. Be-cause Google Street View provides particularly dense coverage of street facades in Vienna, the 360-degree images could be processed to create continuous facade views. A custom sampling logic was developed for the GSV Tiles API. This pro-duced an almost uninterrupted facade panorama from which individual windows can be counted.
Finally, a test calculation was carried out on a sample of Vienna’s Gründerzeit blocks. Box-window counts were calculated for seven blocks in Vienna’s Favoriten district, distinguishing between street-facing and courtyard-facing windows. Street-facing windows were detected using YOLO inference, while courtyard-facing window counts were estimated mathematically. The results were then compared with Google Earth imagery to as-sess the method’s usefulness.
The results for street-facing windows were usable, while the courtyard-side estimates were specula-tive. To estimate courtyard-facing windows, build-ing outlines in OpenStreetMap were measured, and the number of courtyard windows was calcu-lated based on the ratio of interior to exterior fa-cade area. The accuracy of the results therefore depended heavily on the accuracy of the building footprints in OpenStreetMap.
On the street-facing side, the total window count differed by −4%. However, the number of box windows was underestimated by 18%. The ap-proximation method overestimated courtyard-facing windows by an average of 43%, with sub-stantial variation between blocks. The close agree-ment in the total number of box windows (+5%) resulted from offsetting errors and should there-fore be interpreted with caution.
Finally, an error analysis was conducted on the relevant buildings to identify opportunities for improving the algorithm. Most errors (42%) were attributable to discrepancies with OSM geometry. Inference for 23% of the relevant buildings was affected by tree cover. Other causes of error in-cluded buildings that were too tall (15%), dedupli-cation errors (11%), and obstructions from loggias or scaffolding.
This thesis demonstrates that combining Google Street View with an object-detection algorithm can provide a satisfactory method for facade analysis. Handling courtyard-facing windows and evaluat-ing building geometry are the most important pre-requisites for scaling up the calculations.
